DAYONE v2.2 -- NETLIFY 404 FIX (25 OCT 2026)

WHY THE ERROR HAPPENED
The earlier uploaded ZIP kept index.html inside site/. If Netlify published that ZIP
as static files rather than running a build, the deployed root URL had no index.html.

CHOOSE THE METHOD YOU NEED:

A. FIX THE 404 IN ONE STEP (THE SIMPLE METHOD)
    File: DAYONE_v2_2_GIFs_NETLIFY_DROP.zip

    1. In Netlify, open the EXISTING project that displays 404.
    2. Open Deploys > drag-and-drop/manual deploy area.
    3. Drag in this ZIP directly. It has index.html AT THE ZIP ROOT.
    4. Open the EXISTING site URL, not a newly created site.
    5. The site opens, logs workouts, weight, photos, and compares images locally.

    LIMITATION: Manual static uploads do NOT install the Netlify Function.
    Sync to Blobs needs method B.

B. FIX THE 404 *AND* ENABLE PRIVATE NETLIFY BLOBS SYNC
    File: DAYONE_v2_2_GIFs_FULL_NETLIFY_BLOBS.zip

    1. Extract this full source ZIP on a Windows computer.
    2. Double-click DEPLOY_ON_WINDOWS.cmd.
    3. Install free Node.js LTS only if the script asks.
    4. When Netlify asks, link to your EXISTING site.
    5. On Netlify, add environment variable DAYONE_SYNC_KEY with a random,
       unique value at least 20 characters; rerun DEPLOY_ON_WINDOWS.cmd.
    6. Visit https://YOUR-SITE.netlify.app/.netlify/functions/dayone-api .
       401 = function is active and protected (good);
       503 = you still need to set the environment variable;
       404 = the function was not deployed.
    7. In your app Settings, enter the same private key and connect & merge.

IMPORTANT
- No Firebase, GitHub, paid database, or subscription is needed.
- Netlify Free has credit and storage limits.
- Do not make your private sync key public.
- Keep deploying to the SAME site address to retain device records and cloud data.
- The PWA cannot automatically read iPhone HealthKit; use manual XML import.
- If you only want to repair the 404 today, choose method A.
